# Proposal 0005 — Repository governance items for the owner

| | |
|---|---|
| Status | Open; each item is an owner decision, none is made by this change |
| Date | 2026-10-13 |

## 1. Default branch

GitHub's default branch is `main`, an orphan history of 11 documentation and policy commits
(last 2026-02-03) that shares no commits with `master`, where all code lives. Anyone cloning the
repository gets `main` and no code. Options: make `master` the default branch and archive `main`
as a tag; or merge the `main` documents into `master` and then switch. Proposed: the first.

## 2. Licence

There is no `LICENSE` file. Without one, nobody else may use, copy or modify the code, which
blocks reuse by other Constellation repositories under different ownership. Choosing a licence
is the owner's decision; none was added.

## 3. Legacy v1 scripts

`scripts/` holds the v1 runners, selftests and tools (57 tracked files) and `release/` the v1 CLI
bundle. They are outside the v2 gate; their default paths were repointed into the project during the move
to the S: dev root, otherwise they are unchanged. Proposed: once proposal 0001 is accepted,
move them to `legacy/v1/` with their freeze evidence, and keep `docs/history/` as the record.

## 4. Local-only hygiene on the development host

The WBS v1 audit found items that exist only in the local working copy, so this branch cannot fix
them:

- a directory literally named ``k in $Map.Keys){ [void]$keys.Add([string]$k) }`` from a broken
  redirect;
- `proofs/keys/watchtower_authority_ed25519.COMPROMISED.*` and `.PASSPHRASE.*` private keys:
  move them to an offline store or destroy them, and never rotate them back into trust;
- 18 `proofs/trust/*.bak_*` files, a stray top-level `workbench/`, untracked UI duplicates;
- the uncommitted edits on `audit/hygiene-fixes-20260826` are now preserved as commit `5371e93`
  (branch `wip/pre-s-drive-20261013`) and merged into the v2 branch.

## 5. Bridge CORS

The local bridge server (`ui/workbench/watchtower_bridge_server.cjs`, now committed) answers every
origin (`Access-Control-Allow-Origin: *`). If it moves to live-state-surgeon (proposal 0001), restrict it
to the local UI origin there.

## 6. Follow-ups from the move to the S: dev root

- **Constellation path in the generated agent blocks.** `CLAUDE.md`, `AGENTS.md` and
  `docs/canonical/ECOSYSTEM_INTEGRATION.md` point at `../Constellation/...`. With the project now at
  `Constellation/_Covenant-systems/watchtower`, the registry is at `../../Constellation-Network/...`.
  The blocks are generated by Constellation; regenerate them there with a path that does not
  depend on folder depth (for example, resolved from the dev root).
- **NFL inbox registry.** `nfl/config/inbox_registry.json` lists absolute C: paths for every inbox,
  including `watchtower-outbox`. NFL should resolve inboxes relative to the dev root
  (`../watchtower/packets/outbox` from NFL's folder in the same group).
- **v1 release bundle.** Rebuild `release/watchtower_cli_v1` so the shipped installer has the
  project-local defaults, then reinstall into `local/WatchTowerCLI`.
- **Dev-root launchers.** `DEV_SHELL.cmd` and `CHECK_S_DRIVE.cmd` at the dev root call
  `_devenv\` next to themselves, but `_devenv` now lives under `Constellation/Constellation-Network/`.
- **Originals on C:.** The former Local AppData folders and the old C: working copy still exist
  (C: is read-only). Remove them once the S: copy has been used successfully.
